\ SwiftForth 4.1.10 specification profile for the evaluator.
\
\ Sources:
\   https://www.forth.com/swiftforth/
\   https://www.forth.com/swiftforth/revs/
\   https://dl.forth.com/downloads/SwiftForth-linux-eval.tgz
\   Distribution source: SwiftForth/src (kernel, x64, IDE, and Linux files).
\   Distribution manual: SwiftForth/doc/SwiftForth-refman.pdf,
\     latest revision November 11, 2025.
\   Version identity: src/kernel/released.f reports 4.1.10, 05-Aug-2026.
\
\ This maximal static profile inherits the ANS94 profile and adds public and
\ implementation-support words documented by the SwiftForth 64-bit Linux
\ evaluation distribution. Source alternatives are resolved in favor of x64
\ and IDE definitions. The evaluator cannot model separate return/floating
\ stacks, variable stack arity, non-local exceptions, object dispatch, or C
\ ABI calls exactly. Floating items are folded onto the abstract data stack;
\ return-stack-only items are omitted; variable groups retain one item; the
\ first documented alternative is selected; unknown functional names map to x.
\ Parsing metadata is supplied manually for common SwiftForth source words;
\ optional or variable parser payloads are reduced to one representative form.
\
\ The inherited ANS-compatible baseline follows.

\ ANS Forth specification profile (ANSI X3.215-1994 / DPANS94).
\
\ Sources:
\   Official standard: ANSI X3.215-1994, Programming Languages -- Forth.
\   Public last draft submitted to ANSI: https://www.taygeta.com/forth/dpans.html
\   Core glossary: https://www.complang.tuwien.ac.at/forth/dpans-html/dpans6.htm
\   Word-set glossaries: dpans7.htm through dpans17.htm at the same location.
\ The public DPANS94 text says that the printed X3.215-1994 controls if the two
\ conflict.  Stack effects below follow that draft's glossary, with evaluator-specific
\ parser, defining-word, state, and control clauses added before each effect.
\
\ Modeling notes:
\ - This file includes the Core word set, Core Extensions, and all optional
\   word sets in sections 7--17.  It therefore describes a maximal ANS94
\   environment, not a claim that every ANS Forth system implements every word.
\ - The evaluator has one data stack and one fixed effect per word.  This
\   profile selects the Standard's permitted combined-stack form for floating
\   words, represents a double-cell value by one abstract item, and gives a
\   fixed conservative approximation to effects containing i*x/j*x or `...`.
\ - For overloaded n|u arithmetic, the fixed specs below select the signed
\   interpretation where needed to preserve useful result types.  Explicit
\   unsigned and double-unsigned words retain their normative types.
\ - Return-stack and non-local effects (EXECUTE, EVALUATE, CATCH, THROW,
\   ABORT, LOAD, INCLUDED, and similar words) cannot be represented exactly;
\   only their visible fixed data-stack suffix is modeled.
\ - CASE is modeled declaratively for one OF ... ENDOF clause.  The evaluator's
\   structure language cannot express an arbitrary number of OF clauses.
\ - SAVE-INPUT/RESTORE-INPUT and search-order vectors use one representative
\   x or wid before their count because effects of variable arity are not
\   supported.  Conditional result shapes such as FIND and >FLOAT select one
\   representative shape.
\ - LITERAL cannot be declared because `literal` is reserved as a spec-file
\   directive.  :NONAME, MARKER, CODE, LOCALS|, and conditional compilation
\   are listed but exceed the evaluator's current defining/state machinery.
\
\ Format:
\   word [parse mode [delimiter]] [define [mode]] [control role]
\        [state mode] ( inputs -- outputs )
\   literal kind ( -- outputs )

\ One-clause CASE approximation.  OF consumes both selector and test on both
\ paths; ENDCASE is therefore a no-op.  This preserves the net stack shape
\ while avoiding an unrepresentable conditionally retained selector.
syntax: CASE <test-expression> OF <of-branch> ENDOF <default-branch> ENDCASE
  effect:
    CASE
    <test-expression> OF
    either <of-branch> <default-branch>
    ENDCASE
